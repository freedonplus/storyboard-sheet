# 拼板输出规格

## 一、格数与比例

每格默认 16:9。整板比例 = `(列数×16) : (行数×9)`。

| 格数 | 网格 | 整板比例 | 用途 |
|---|---|---|---|
| 4 | 2×2 | 16:9 | 短片段、单场戏 |
| 6 | 3×2 | 8:3（2.67，偏宽） | 中等段落，横向阅读 |
| 6 | 2×3 | 32:27（1.19，偏方） | 竖版展示、手机端 |
| 8 | 3×3（1 格标题卡） | 16:9 | 标准段落，推荐 |
| 9 | 3×3 | 16:9 | 完整段落，无标题卡 |

要求严格 16:9 时优先选 n×n 网格，或把标题卡占用第 9 格。

## 二、像素

- 单帧生成：1536×864（16:9）。
- 格子尺寸：1280×720；整板 3×3 = 3840×2160。
- 交付：PNG 原图（全分辨率）＋ JPG 预览（长边 2560，质量 88）。
- 3×4 以上超大板可把格子降到 960×540，整板保持整数像素。

## 三、叠字版式

- 格底半透明条：高 78px（720 高格子的约 11%），填充 `ARGB(170,6,8,11)`，顶部 2px 分隔线 `ARGB(255,30,36,44)`。
- 左侧：镜头号（加粗、亮蓝 `ARGB(255,96,168,255)`，27px）+ 时长（灰 `ARGB(255,150,168,186)`，18px），基线与镜头号对齐。
- 右侧：镜头名（白 `ARGB(255,238,242,247)`，22px），右对齐，左右各留 26px。
- 文字超出格宽时按比例缩字号，不换行、不截断。
- 标题卡：深底 `ARGB(255,14,18,23)`，片名 54px 加粗居中偏上，下列副标题（STORYBOARD / 格数 / 时长 / 比例）、分镜内容提要、质感说明。
- 字体统一 Microsoft YaHei；不描边、不投影。

## 四、镜头单 JSON 规范

镜头单是全片的**单一事实源 + 溯源档案**：锚点句只有一份，各格引用；每格定稿后把生成原句与种子回写。

### 字段说明

拼板必需（build-board.ps1 读取）：

- `id`：镜头号，全片连续，`SH001` 起。
- `time`：成片时间区间，用 `-` 连接，秒保留一位小数；相邻镜头区间必须首尾相接（上一格终点 = 下一格起点）。
- `name`：三到六个字的镜头名，写动作或拍法，不写形容词。
- `file`：`PanelsDir` 下的文件名，缺文件时拼板脚本报错退出，不用占位图。
- `shots` 按阅读顺序排列（左→右、上→下）。
- `title_cell` 为 `true` 且 `shots` 数 = `cols×rows-1` 时，最后一格画标题卡；否则空格留深底。

一致性必需（validate-shots.ps1 校验）：

- `anchors`：八句锚点原句的唯一家。各格 `prompt` 必须原句包含 `characters` 每条、`blocking`、`axis`、`lighting`、`props`、`negative`——校验脚本逐条做子串比对，改一个字都会 FAIL。
- `cameras`：机位表。`id` 唯一；`shots[].camera` 必须引用表中存在的机位。
- `camera` / `framing`：本镜机位编号与景别。
- `cast`：本格出场角色名数组（对应 `anchors.characters` 每条的名字前缀，如 `["忍者"]`）。校验时只要求出场角色的锚点句原句进 Prompt；缺省则要求全部角色锚点都出现。
- `in_state` / `out_state`：入格/出格状态。第 N 格 `out_state` 与第 N+1 格 `in_state` 必须**逐字相等**；位置、朝向、动作相位、接触点、表情强度五项落字。
- `scene_break`：换场断链标记。为 `true` 时本格 `in_state` 不要求与上一格 `out_state` 相同，参考图链也在此断开、重开首格。不允许默默断链。
- `cut_in` / `cut_out`：切点类型 + 接住什么，见 [continuity.md](continuity.md#六切点类型写清接住什么)。
- `screen_side`：本格**真正可见**的角色在画面里的侧位，值只有 `left`／`center`／`right`，键必须在 `cast` 里；Prompt 必须原句含“{角色}在画面左侧／中部／右侧”。同场相邻格中两个都出镜的角色，左右次序不许翻转，除非该格 `reverse_shot: true`（校验脚本按次序符号比对，翻转直接 FAIL）。
- `reverse_shot`：反打／过肩格显式标记。仅允许成对出现，下一格必须切回原侧位；缺省为 `false`。
- `ref_binding`：本格参考图的槽位绑定，`[{"slot":"图片1","subject":"小狗","role":"identity"}]`。`slot` 必须与工具实际收到的图片顺序一致；`role` 用 `identity`（身份素材）或 `layout`（上一格画面／构图参考）；一槽只能绑一个主体，Prompt 必须出现该 `slot` 字样与对应“仅提供…”用途句。首格无参考图时写空数组。
- `anchors.negative_parts`：负向四段（`base`／`anatomy`／`geometry`／`separation`），校验脚本要求每格 `prompt` 原句含全部四段；`anchors.negative` 保留兼容旧版，仍会校验。
- `style_preset`：开板时选定并写死的风格预设，取值只能是 `realistic`／`line_bw`／`graphite`／`manga_tone`／`cel2d`／`guoman3d`／`aaa_cg`／`watercolor` 之一；对应四件套（质感句／色板／阴影方式／负向补充）见 [prompt-templates.md](prompt-templates.md#七风格预设表开板先问一次)。一条板只允许一个值，换风格按新任务处理。

溯源字段（生成后回写，不回写不交付）：

- `prompt`：该格实际提交给生图模型的完整 Prompt 原句（含全部锚点句），一字不改。拿到 JSON 即可逐格复现。
- `ref`：本格使用的参考图链，`null` 表示首格/断链重开；`"SH003"` 表示以 SH003 成品为参考；`"SH001+SH003"` 表示双参考。
- `seed`：生图工具返回的种子；工具不给就保持 `null` 并在 `qa` 里注明。
- `qa`：单格质检结论与备注（通过/重出原因/遗留风险）。

### 兼容约定

旧格式（只有 `id`/`time`/`name`/`file`）仍可被 `build-board.ps1` 拼板，但 `validate-shots.ps1` 会按缺一致性字段报 FAIL——新镜头单一律按完整字段写。
