# 衔接卡：让相邻两格接得上

分镜不衔接，几乎都是同一个原因：**每格独立构图，没有共用空间坐标、没有轴线、上一格结束状态没有传给下一格**。本卡把这四件事压成必填项，缺一项就不允许开图。所有锚点句集中住在镜头单顶层 `anchors` 块（单一事实源），各格从这里原句复制，校验脚本逐条比对，改一个字都会 FAIL。

## 一、三个必须先在内容卡里钉死的东西

| 项 | 作用 | 写在哪 |
|---|---|---|
| 空间蓝图 | 所有角色在同一坐标系里的固定位置，全组原句复制 | 内容卡 `blueprint` |
| 轴线与左右定则 | 机位只能在一侧，角色在画面里的左右不互换 | 内容卡 `axis` |
| 机位表 | 每镜一个机位编号，位置/高度/朝向/景别写死，相邻镜只能按表小步移动 | 内容卡 `cameras` |

## 二、空间蓝图怎么写

用**场景固定物**做坐标，不用画面方位。写完自查：把所有"左/右/前/后"字样删掉，位置仍能唯一确定。

```text
空间蓝图（全组原句复制）：小狗坐在白色停止线与斑马线第一条白条之间的沥青上，臀部离停止线约 45 厘米、离白条约 30 厘米，身体正对信号灯杆；小猫坐在小狗靠缘石一侧约 25 厘米、离停止线再远约 15 厘米的位置，坐姿、尾巴绕在前爪上；两者都在停止线之后、白条之前，不踩白条。老人从斑马线右端的缘石缺口进入路口。
```

要点：原点选一个看得见的实体（白条端点、缘石缺口、门框、桌角），每个角色给「距哪个固定物多远 + 在哪一侧 + 身体朝向谁」。

## 三、轴线规则（防"左右互换"）

- 取两个主要角色（或角色与主要目标，如信号灯）的连线为轴，**全组机位只能在这条轴的一侧**。
- 写一句左右定则并全组照抄：`在道路侧机位看，狗在左、猫在右；老人始终从猫那一侧（缘石缺口）进入。`
- 必须越轴时（侧向中景、反打），显式标注「越轴镜头」，并给它一个插入镜或视线对齐作为过渡；一格里完成，不让下一个正打镜头继续越轴。
- 相邻两镜的机位水平夹角 ≤ 90°，避免跳到近乎相反的方向。

## 四、机位表

```text
C1：停止线后方 2.5 m 沥青上，离地 20 cm，水平朝信号灯杆，广角，运动：沿白条方向慢推 20 cm。
C2：狗猫侧后方 1.2 m，离地 60 cm，仰角约 20°，朝灯与倒计时屏，近景，运动：右摇 10° 后下摇 8°。
C3：停止线后方 3.5 m，离地 120 cm，水平朝缘石缺口（与 C1 约 90°），中景，运动：沿停止线方向横移 30 cm。
```

相邻镜变化不得超过：高度差一个身位、景别连跳两级（全景直跳近景必须插中景）、夹角 90°。

## 五、尾态 / 首态接力（最硬的一条）

每格写两条状态，镜头单 JSON 用 `in_state` / `out_state`：

```text
SH001 out_state：狗坐姿不动、视线上仰对准红灯；猫尾巴绕前爪、头已转向信号灯；两者仍在蓝图原位，未移动。
SH002 in_state：（必须与 SH001 的 out_state 逐字相同）
```

硬规则：**第 N 格 out_state 与第 N+1 格 in_state 逐字一致**，禁止重写、禁止"基本一致"。位置、朝向、动作相位、接触点、表情强度五项都要落字。换场必须显式标 `scene_break: true`（参考图链同时断开、重开首格），不允许默默断链；校验脚本对未标记的断链直接 FAIL。

## 六、切点类型（写清接住什么）

| 类型 | 用法 | 写法 |
|---|---|---|
| 动作切 | 动作未完时切 | 接住左脚刚落地的那一帧 |
| 同构图跳切 | 时间省略 | 同一机位同一构图，只换时间状态 |
| 视线切 | 反应镜 | 接住视线定住的人／物 |
| 声音先行切 | 下一格先出声 | 脚步声先入，画面后到 |
| 硬切 | 默认 | 接住上一格已完成的动作 |

## 七、参考图链（执行层面的最大杠杆）

生成顺序按机位表串行，不要一次并行全部格：

1. 先出 C1 首格（定下空间、比例、光线、角色外观）。
2. 后续格把**上一格成品**作为参考图传入，指令固定写：`只参考空间布局、角色比例、地面关系与光线方向，不照抄构图`。
3. 每格仍保留四件套锚点句（角色锚点 + 空间蓝图 + 光位 + 画幅）。
4. 只限同一场戏内传递；换场就断链，用新首格重开。

## 八、比例锚（防角色忽大忽小）

选一个场景固定尺寸物写进每格：白条宽约 45 厘米、缘石高约 15 厘米、护栏立柱间距约 1.2 米。角色尺寸用锚换算：`狗高约 20 厘米，约白条宽的一半`。这样即使景别变化，观众也能确认是同一个空间。

## 九、交付前自查

自查分两层：先跑机器，再过人眼。

机器校验（`scripts/validate-shots.ps1`，FAIL 即阻断）：

- 相邻格 `out_state` 与下一格 `in_state` 是否逐字相等
- 时间区间是否首尾相接、镜头号是否连续
- 每格 `prompt` 是否原句包含全部 anchors 与出场角色锚点
- 机位引用是否存在、参考图链是否只指向更早的格

人眼复核（机器查不出的语义问题）：

- 角色左右位置是否全组一致（有没有一格狗跑到右边）
- 相邻机位夹角是否 ≤ 90°，高度差是否超一个身位
- 同一场景物（白条、缘石、护栏）在两格中形态是否一致
- 视线是否指向同一目标（看灯就全看灯，别一格看灯一格看人）
- 光位句是否同一句，色温有没有偷偷变暖
- 比例锚是否每格都在，角色尺寸有无跳变
- 状态卡是否全组同一句，灯态／数字／天气有无自相矛盾

## 十、溯源回写（高溯源）

每格定稿后立刻把四样写回该 shot，缺一项不算完成：

| 字段 | 内容 | 作用 |
|---|---|---|
| `prompt` | 提交给生图模型的完整原句，一字不改（含全部锚点句与入格/出格状态） | 任何人拿 JSON 可逐格复现 |
| `ref` | 参考图链：`null`=首格/断链，`"SH003"`=单参考，`"SH001+SH003"`=双参考 | 定位一致性问题的传播路径 |
| `seed` | 生图工具返回的种子；工具不给就保持 `null` 并在 `qa` 注明 | 精确复现 |
| `qa` | 单格质检结论：通过／重出次数与原因／遗留风险 | 穿帮追责到具体格 |

穿帮排查顺序：看出问题的格 → 读它的 `ref` 找到参考来源 → 对比两格的 `prompt` 哪句锚点被改了 → 修 anchors 或该格 Prompt → 只重出受影响的格与其下游（参考图链上挂在它后面的格都要复核）。

## 十一、可变状态卡（灯态／时间／天气／门）

同一场戏里会变化、且观众会读出含义的对象，必须给一句固定状态并全组原句复制。最常穿帮的是信号灯。

| 对象 | 正确形态 | 常见穿帮 |
|---|---|---|
| 车辆信号灯（面向本车道） | 三圆盘（红／黄／绿），亮的是纯色圆盘或绿色直行箭头，与行人灯分开、朝向车流 | 圆盘里画人形；红灯亮却像绿灯；灯与车流方向矛盾 |
| 行人信号灯 | 红＝**站立不动**人形；绿＝**行走**人形；灯箱多为方形、比车辆灯小 | 红色行走人形；绿灯里画站立人；圆形大灯箱里塞人形 |
| 行人倒计时屏 | 数字颜色与服务灯色一致；红灯时显示剩余红秒数 | 红灯配绿色数字；数字与灯分属不同方向 |
| 车道箭头／地面标线 | 与当前通行权一致 | 直行绿灯却配“禁止直行”标牌 |
| 时间／天气／水位／门 | 一句固定状态，跨格不改 | 一格白天一格黄昏；一格关灯一格开灯 |

硬规则：

1. **通行权只能有一个结论**。写“行人红灯＋车辆直行绿灯”时，必须补一句“车辆正沿本车道直行通过路口”，否则灯与车流会打架。
2. **写清哪盏面向谁**：面向本车道车辆 / 面向过街行人 / 面向对向车道，不能笼统写“信号灯”。
3. **不允许自造符号**：圆盘里画人形、红色行走人形、绿灯配红数字，一律视为穿帮。
4. 状态卡与站位卡、光位句一起进四件套，逐格原句复制，统一收进 `anchors.props` 块。
